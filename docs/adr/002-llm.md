# ADR 002 — T2 fast LLM provider (T03)

Date: 2026-10-23 · Status: **Day 1 done, gate PASSED on Groq. Day 2 pending.**

## Run

`swift run bench-llm --n 50 --providers groq,gemini --pace-ms 6000` on the Mac (KSA network), 2026-10-23
~16:55–17:24 UTC. TTFT = request start to first non-empty content token over the OpenAI-compatible stream.
Arabic check = 10 Saudi-dialect questions from `bench/llm-ar.jsonl` (synthetic notes): pass if most words are
Arabic script, the expected fact appears, and ≤ 3 lines.

Gate `ttft_p50_ms <= 600` for ≥ 1 provider: **PASS** (all three Groq models). Day 2 run still needed per T03.

## Free-tier limits (checked 2026-10-23)

| Provider | Limits | Source |
|---|---|---|
| Groq (all 3 models above) | gpt-oss-120b, qwen3.8-27b: 1,000 requests/day, 8,000 tokens/min. allam-2-7b: 7,000 requests/day, 6,000 tokens/min | live `x-ratelimit-*` response headers; https://console.groq.com/docs/rate-limits (page labels its table "Developer plan") |
| Gemini | Not published per model; only in AI Studio (https://aistudio.google.com/rate-limit). Live: `gemini-3.5-flash` returned 429 after ~15 requests; flash-lite timed out / 503 on ~half. No rate-limit headers sent | https://ai.google.dev/gemini-api/docs/rate-limits |

One answer costs ~550 tokens, so Groq's 8k TPM allows ~14 answers/minute per model and 1,000/day: enough for
~30 questions per call (PRD assumption 3).

## Data-use terms (checked 2026-10-23)

- **Groq**: "By default, Groq does not retain customer data for inference requests"; logs for abuse checks up to
  30 days; Zero Data Retention can be switched on in console Data Controls.
  https://console.groq.com/docs/your-data. Training on API data is not stated on that page (the DPA governs it).
- **Gemini free tier**: Google "uses the content you submit … to provide, improve, and develop" products, and
  "human reviewers may read, annotate, and process your API input and output". It says not to send sensitive or
  confidential data to unpaid services. Paid tier: prompts not used to improve products.
  https://ai.google.dev/gemini-api/terms
- Both serve Saudi Arabia (Gemini: https://ai.google.dev/gemini-api/docs/available-regions; Groq: no official
  list found, community post says worldwide, with a Dammam data centre).

## Decision

1. **Primary: Groq `qwen/qwen3.8-27b`** with `reasoning_effort: none`: fastest (109 ms p50) and 10/10 Arabic.
   Risk: Groq lists it as **Preview**, so it can disappear.
2. **Fallback 1: Groq `openai/gpt-oss-120b`** (Production model, 384 ms, 10/10). Separate per-model quota.
3. **Fallback 2: Gemini** only as a last resort: free tier was rate-limited and slow today, and its terms allow
   Google to train on and human-review prompts. Meeting notes go to it only if the owner accepts that
   (see legal.md); confidential calls never use it.
4. `allam-2-7b` works (386 ms, 10/10) but is no longer in Groq's model docs; not used.
5. T11's `LLMProvider` needs the per-model extra body fields (`reasoning_effort` etc.); `Probe` already merges
   them, `AnswerLLM.request` does not yet. T11 owner to add.
