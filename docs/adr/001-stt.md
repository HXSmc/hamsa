# ADR 001 — STT engine (T02)

Date: 2026-10-23 · Status: **PROVISIONAL — every number below is from TTS audio, not real calls.
The real gate (`--set bench/ar-sa --with-zoom-load`) waits on T02a (owner-recorded calls).**

## Set and method

- Set: `bench/synth/` from `bench/make-synth-set.sh`: 20 Arabic clips (`say -v Majed`, voice `ar_001` = MSA,
  sentences written in Saudi white dialect about a startup; 5 of 20 contain English tech terms), 10 English
  clips (`say -v Samantha`), 16 kHz mono WAV, 3–6 s each, `.txt` reference next to each. Clean TTS audio is
  far easier than a Zoom call: expect real WER and lag to be worse.
- Run: `cd mac && swift run bench-wer --set ../bench/synth --engine all --adr ../docs/adr/001-stt.md --label idle`.
  `--engine all` re-runs the binary once per engine so peak RSS is per engine.
- WER: word-level edit distance / reference words, after `Probe.normalize` (tashkeel, alef/yaa/taa-marbuta,
  digits, case) plus punctuation and invisible marks stripped. Numbers are not verbalized (`20,000` ≠
  `عشرين ألف` counts as errors).
- Partial lag (per word): first time the word appears at its index in any partial/final, minus the word's end
  time in the audio (taken from the engine's own final word timestamps).
  - Dictation (`DictationTranscriber`, SpeechAnalyzer, macOS 26): audio fed in real time, 100 ms chunks, 2 s
    silence tail, `volatileResults` + `audioTimeRange`.
  - WhisperKit 1.1.1 (`argmax-oss-swift`): every 1 s re-decode all audio so far (growing window; clips < 30 s)
    on a simulated real-time clock (a decode starts at max(step boundary, previous decode done)),
    `language` forced, `wordTimestamps: true`. This is the "chunked windows" candidate from the TDD.
- Memory: `rss_mb` = `getrusage` peak of the bench process. Dictation runs in a system daemon, so its in-process
  RSS is tiny; `daemon rss_mb` = peak summed RSS of processes named *speech*/*dictation*. WhisperKit's
  CoreML/ANE memory is only partly in RSS: first (cold) run with compile had peak footprint 499 MB
  (`/usr/bin/time -l`), warm runs 127 MB RSS.
- `pageouts_growth` is `vm_stat` system-wide: 5+ other Claude sessions ran on this 8 GB Mac, so it is never 0
  here and says nothing about the engines. Every gate line below FAILS only on that column for Dictation.
- `--with-zoom-load` skipped (needs the owner). Instead `cpu-load` = a `say` render loop + one `yes` core.

## Asset check

`DictationTranscriber` `ar_SA` and `en_US`: `AssetInventory.assetInstallationRequest` → `downloadAndInstall()`
worked; status `installed`; no permission prompt for a CLI. (ADR 000: `SpeechTranscriber` has no Arabic.)

## Decision (provisional)

| Gate (synth) | wer_ar ≤ 0.30 | wer_en ≤ 0.15 | lag_p50 ≤ 700 ms | rss ≤ 900 MB | pageouts = 0 |
|---|---|---|---|---|---|
| Dictation | 0.198 ✅ | 0.099 ✅ | 403 ✅ | 22 + 106 daemon ✅ | not measurable here |
| WhisperKit large-v3-turbo | 0.119 ✅ | 0.037 ✅ | 2063 ❌ | 127–434 RSS, 499 cold footprint ✅ | not measurable here |
| WhisperKit small | 0.167 ✅ | 0.062 ✅ | 1385 ❌ | 250 ✅ | not measurable here |

- **Arabic: `DictationTranscriber(ar_SA)` for live partials** — the only engine under 700 ms lag (403 ms p50,
  unchanged under CPU load). **WhisperKit large-v3-turbo for final segments**: 3× fewer Arabic errors on pure
  Arabic (0.041 vs 0.165) but ~2 s lag in chunked mode, so it fits re-decoding a VAD-closed segment, not partials.
- **English: `DictationTranscriber(en_US)`** for partials (0.099, 403 ms); same WhisperKit final pass optional.
- T08 builds: Dictation partials → T0 card match; WhisperKit large-v3-turbo final re-decode → transcript +
  T1/T2. RAM for both fits the 1.5 GB budget (`concurrent` run above, ≈ 563 MB of measured peaks).
- If T02a real calls push Dictation `wer_ar` > 0.30 (dialect; Majed is MSA), fall back to Plan B (WhisperKit
  chunked, 2–3 s lag) and/or T02b (Saudi fine-tune).

## Method limits (matter for the real T02a clips)

- WhisperKit is benched as growing-window re-decode, not the TDD's 5 s window: decode time grows with clip
  length, so the ~2 s lag only holds for these 3–6 s clips; 30–60 s clips will be slower unless T08 windows.
- Lag is matched by word index: an early insertion/deletion shifts later words and they drop out of the lag
  stats. Compare `lag words` with the reference word count (here 206–211 lag words vs 207 reference words; lag words count the engine's own final words, so they can exceed the reference).
- `ru_maxrss` does not capture CoreML/ANE memory well (WhisperKit small showed 250 MB vs large 127 MB warm);
  use the 499 MB cold peak footprint against the 900 MB line.
- `--set bench/ar-sa`: language comes from the path; put English clips under `en/` (or name them `en*`),
  else every clip is scored as Arabic and `wer_en` is skipped (n/a, not FAIL).
- `--with-zoom-load` exists (labels the run `zoom-load`, prints the owner instruction) but was not run.

## Not verified

- Real Saudi speech, Zoom audio, 30-min soak, `pageouts_growth=0` on a quiet machine: all wait on T02a + owner.
- Linux build of the package after adding WhisperKit (product is `.when(platforms: [.macOS])`, code under
  `#if canImport(WhisperKit)` / `#if os(macOS)`); macOS CI only.
